2. Core Clarifications (Now Fixed)

2.1 “Completed” is an action, not a status
	•	Vendor clicks: Complete Job
	•	System sets: Ready for Scheduling

⸻

2.2 Submission Failed = vendor-side failure

Covers:
	•	government rejection
	•	system error
	•	wrong data
	•	doc mismatch

👉 Keep broad for V1

⸻

2.3 Returned = internal rejection

Covers:
	•	QA failure
	•	missing info
	•	incorrect typing

👉 Strictly internal-only action

⸻

2.4 On Hold = internal-controlled pause
	•	Only internal team can set
	•	Vendor cannot directly set
	•	Vendor can only request via note/event

⸻

2.5 Wallet deduction is system-controlled

Happens only when:
→ status becomes Ready for Scheduling

Must be:
	•	one-time
	•	idempotent
	•	protected

⸻

3. Final Status Definitions

New
	•	Job created and sent to vendor
	•	Vendor hasn’t started

⸻

In Process
	•	Vendor is actively working
	•	Includes:
	•	typing
	•	submission attempts

Triggered by:
→ vendor opens job (auto)

⸻

Submission Failed
	•	Vendor attempted government-side process and failed

Requirements:
	•	reason required
	•	optional note

⸻

Returned
	•	Internal team sends job back for correction

Requirements:
	•	reason required

⸻

Ready for Scheduling
	•	Vendor marked job complete
	•	System:
	•	validates
	•	deducts wallet
	•	unlocks scheduling

This is:
→ final typing state

⸻

On Hold
	•	Internal pause
	•	used for:
	•	clarification
	•	missing docs
	•	waiting client

⸻

Cancelled by Vendor
	•	Vendor cancels job

⸻

Cancelled by User
	•	Internal team cancels job

⸻
