Run a full-app diagnostics + improvement pass (React/Tailwind website).

GOAL
- Find anything broken, fragile, inconsistent, or hard to use.
- Even if it “works,” suggest a simpler/better approach for UX + code.
- Focus on making the site easier + cleaner for the end user.

SCOPE (do ALL)
1) UI/UX Audit
- Navigation clarity (active states, mobile menu, spacing, CTA hierarchy)
- Typography + readability (line length, font sizes, contrast)
- Layout stability across breakpoints (no collapsed widths, no overflow)
- Forms (labels, validation, errors, loading states, success messages)
- Consistency (buttons, cards, headings, spacing scale)

2) Layout Diagnostics (VERY IMPORTANT)
- Identify any sections where text wraps character-by-character or containers collapse.
- In the Preview iframe specifically, inspect computed widths and flex/grid rules.
- Fix root causes (min-w-0 / basis-0 / flex-1 / grid constraints).
- Provide a list of each fixed section and what was changed.

3) Accessibility (A11y)
- Semantic HTML (h1-h2 order, landmarks)
- Keyboard navigation + focus rings
- ARIA where needed
- Color contrast checks

4) Performance + Best Practices
- Image sizes + lazy loading
- Reduce unnecessary re-renders
- Remove unused CSS/classes/components
- Bundle/asset sanity

5) Code Quality + Simplification
- Identify duplicated UI patterns → extract reusable components (Button, Section, Card)
- Improve folder structure
- Remove hacks (global “w-full” bandaids) and replace with correct layout patterns
- Ensure tailwind config and global styles aren’t fighting components

DELIVERABLES (MUST RETURN)
A) A prioritized list:
   - P0 Critical (breaks layout/UX)
   - P1 Important (confusing/inconsistent)
   - P2 Nice-to-have (polish)
B) For each item: location (file/component), cause, fix, and the exact code change.
C) A “Simplify Plan” with 5–10 concrete refactors that reduce complexity.
D) After changes: test checklist results for:
   - Desktop (wide), laptop, tablet, mobile
   - Chrome + Safari behavior (as much as possible)
   - Preview iframe behavior (Replit)

RULES
- Don’t rewrite the whole project. Make targeted, high-impact changes.
- Keep the existing design style unless a change clearly improves clarity.
- Verify fixes in the Replit Preview iframe before claiming “fixed”.
