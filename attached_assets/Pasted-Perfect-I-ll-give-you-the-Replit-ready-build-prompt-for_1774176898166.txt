🧠 REPLIT BUILD PROMPT

Work Order View — Medical & ID Portal

⸻

Build a Work Order Detail Page for the Medical & ID Portal with a clean, Apple-style UI and clear operational structure.

This page must show the full lifecycle of a work order across 4 independent tracks:
	1.	Medical Typing Job
	2.	Medical Appointment
	3.	EID Typing Job
	4.	Biometrics Appointment

The goal is:
	•	zero confusion
	•	one-glance clarity
	•	clear next actions
	•	strong visual hierarchy

⸻

1. Page Layout (STRICT ORDER)
	1.	Header
	2.	Blocker + Summary Bar
	3.	4 Track Cards Grid
	4.	Smart Action Bar
	5.	Unified Timeline

Do not reorder.

⸻

2. Header

Left:
	•	Applicant Name (bold, large)
	•	Work Order ID (lighter text)
	•	Service Type

Right:
	•	Overall Status Badge (pill style)

Style:
	•	white/glass background
	•	soft shadow
	•	rounded corners (16px)
	•	spacing: clean, minimal

⸻

3. Blocker + Summary Bar

Top line:
	•	Show blocker in red:
“Blocker: [Module] — [Status]”

Example:
Blocker: Medical Appointment — Awaiting Meeting

Below:
	•	Show compact progress summary:

Medical: Typing ✔ → Appointment ⏳
EID: Typing ✔ → Biometrics ✔

Rules:
	•	use icons or subtle indicators (✔, ⏳)
	•	keep it lightweight
	•	no heavy cards

⸻

4. Track Cards Grid

Layout:
	•	Desktop: 2x2 grid
	•	Mobile: stacked

Each card must follow the same structure:

[ Icon + Title ]
[ Status Badge ]
[ Key Info ]
[ Divider ]
[ Actions ]

⸻

Card 1 — Medical Typing

Content:
	•	Title: Medical Typing
	•	Status badge
	•	Vendor name
	•	Reference number (if available)

Actions:
	•	View Job
	•	Change Vendor
	•	Put on Hold

⸻

Card 2 — Medical Appointment

Content:
	•	Title: Medical Appointment
	•	Status badge
	•	Center name
	•	Time
	•	Assigned PRO

Actions:
	•	View Appointment
	•	Reschedule
	•	Contact PRO

⸻

Card 3 — EID Typing

Content:
	•	Title: EID Typing
	•	Status badge
	•	Vendor name

Actions:
	•	View Job
	•	Follow Up

⸻

Card 4 — Biometrics

Content varies:

IF biometrics_required = false:
	•	Show:
“No biometrics required”
(green muted style)

IF scheduled:
	•	Show center + time

IF completed:
	•	Show completed badge

Actions:
	•	Book
	•	View
	•	Reschedule

⸻

5. Status Badge System

Use pill-style badges with colors:
	•	Grey → Draft/New
	•	Blue → In Process / Awaiting
	•	Amber → Ready
	•	Green → Completed
	•	Red → Returned / Failed / No Show

⸻

6. Smart Action Bar

Position:
	•	below cards
	•	sticky on scroll

Behavior:
	•	show ONE primary action depending on state

Examples:
	•	Medical Typing ready → “Schedule Medical”
	•	Awaiting Meeting → “Contact PRO”
	•	No Show → “Reschedule”
	•	Returned → “Fix & Resend”

Style:
	•	strong primary button
	•	minimal secondary actions

⸻

7. Unified Timeline

Single vertical timeline (NOT separate per module)

Include events from all modules:
	•	typing created
	•	sent to vendor
	•	vendor started
	•	typing completed
	•	appointment scheduled
	•	check-in
	•	result issued
	•	biometrics completed

Design:
	•	vertical line on left
	•	dot per event
	•	timestamp small
	•	category color-coded

⸻

8. Interaction Rules
	•	Cards slightly lift on hover (scale 1.02)
	•	Smooth transitions (200–300ms)
	•	Buttons have subtle feedback
	•	Avoid clutter

⸻

9. Data Structure (Required)

Work Order:
	•	id
	•	applicant_name
	•	service_type

Medical Typing:
	•	status
	•	vendor
	•	ref_no

Medical Appointment:
	•	status
	•	center
	•	time
	•	pro

EID Typing:
	•	status
	•	vendor
	•	biometrics_required

Biometrics:
	•	status
	•	center
	•	time

⸻

10. Blocker Logic

Determine blocker based on priority:
	1.	Returned / Failed / No Show
	2.	Awaiting / In Process
	3.	Ready
	4.	Completed

Lowest-progress critical module becomes blocker.

⸻

11. Design Style
	•	Apple-style minimal UI
	•	clean typography (SF / Inter)
	•	soft shadows
	•	rounded corners
	•	subtle gradients
	•	no heavy borders
	•	high spacing discipline

⸻

12. Constraints
	•	Do not merge module statuses
	•	Do not hide any track
	•	Do not overload with text
	•	Focus on clarity over features

⸻

Deliver:
	•	responsive UI
	•	clean layout
	•	reusable card components
	•	modular structure
	•	easy to extend later—
